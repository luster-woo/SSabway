# 대구역 표지판 인식

사용자가 찍은 사진에서 역 안내 표지판을 찾아 **41개 표지판 중 어느 것인지** 알려주는 모델입니다.
실내에서 GPS가 안 잡히는 문제를 표지판 인식으로 대신 풀어 길안내에 쓰는 것이 목적입니다.

**실전 정확도 52/56 = 92.9%** (학습에 쓰지 않은 사진 56장 기준)

---

## 1. 어떻게 동작하나

한 장의 사진이 두 개의 모델을 순서대로 거칩니다.

```
사진 → EXIF 회전 보정 → 표지판 검출(YOLO) → 박스 선택 → 크롭 → 분류(ResNet18) → 확신도 판정 → 결과
```

| 단계 | 하는 일 | 설정 |
|---|---|---|
| EXIF 보정 | 폰을 세로로 들고 찍은 사진을 똑바로 세움 | `ImageOps.exif_transpose` |
| 검출 | 사진에서 표지판 위치를 찾음 (클래스 1개: `sign`) | YOLOv8n, conf 0.25, 960px |
| 박스 선택 | 여러 개 찾으면 가장 크고 중앙에 가까운 것 채택 | `면적 × (0.5 + 중앙근접도)` |
| 크롭 | 박스에서 상하좌우 12% 여유를 두고 잘라냄 | margin 0.12 |
| 분류 | 잘린 표지판이 41개 중 어느 것인지 판단 | ResNet18, 입력 128×448 |
| 판정 | 확신도가 낮으면 답하지 않음 | conf < 0.40 → `미분류` |

**왜 2단계로 나눴나** — 표지판은 사진에서 작게 찍히는데 사진 전체를 224×224로 줄이면 글자가 뭉개집니다.
먼저 표지판만 잘라내면 해상도를 글자에 온전히 쓸 수 있어, 문구만 다른 비슷한 표지판을 구분할 수 있습니다.

### 전체 흐름

```bash
# 1) 표지판 박스 초벌 생성 (제로샷 검출, GPU 1분)
python src/01_bootstrap_boxes.py --data 0721_data_split --out boxes.json

# 2) 박스 검수 — 브라우저가 열립니다 (아래 4-1 참고)
python src/annotator.py

# 3) 크롭 + YOLO 데이터셋 생성 (1분)
python src/03_make_crops.py

# 4) 학습 (검출기 40분 + 분류기 5분, GPU 기준)

python src/04_train.py --step cls --arch resnet18 --out-cls models/classifier_resnet18.pt

# 5) 실전 사진으로 평가
python src/05_two_stage_eval.py --det <검출기.pt> --cls models/classifier_resnet18.pt \
    --data <실전 사진 폴더> --answers data/answers/test_all.csv --out report.html
```

3~5번은 `python src/run_after_review.py` 로 한 번에 돌릴 수도 있습니다.

### 4-1. 박스 검수 도구 (`annotator.py`)

자동 검출한 박스는 형광등·바닥·모니터를 표지판으로 잡는 경우가 많아 **사람 검수가 필수**입니다.

```bash
python src/annotator.py     # http://localhost:8765 자동 열림
```

- 잘린 결과가 갤러리로 쭉 나옵니다. **제대로 잘린 건 그냥 두면 됩니다.**
- 잘못된 것만 클릭 → 원본에서 마우스로 드래그해 박스를 다시 그림
- `Space` 확정·다음 / `1` `2` `3` 다른 후보 박스 / `X` 표지판 없음 / `Esc` 갤러리로
- 노란 테두리 = 자동으로 의심 표시한 것 (여기부터 보면 효율적)
- 모든 동작은 즉시 `data/annotations.json` 에 저장 → 창을 닫아도 이어서 작업 가능

**이 저장소의 `data/annotations.json` 에는 이미 463장의 검수 결과가 들어 있습니다.**
다시 검수할 필요 없이 3번 단계로 바로 가면 됩니다.

## 5. 개발하면서 알아낸 것들

성능을 좌우한 문제들입니다. 비슷한 작업을 할 때 같은 함정을 피해보세요~~


### EXIF 회전 정보 유실 — 가장 큰 원인이었음

원본 사진을 1024px로 리사이즈하는 과정에서 EXIF 회전 정보가 날아가,
**학습 데이터의 44%(633장)가 옆으로 누운 채** 학습되고 있었습니다.
실전 사진은 정방향이라 모델이 본 적 없는 형태를 받고 있었던 셈입니다.

`manifest.csv` 의 원본 경로로 되짚어가 orientation을 복구했고, **정확도 50% → 63.6%**로 올랐습니다.

> **추론 코드에서도 반드시 `ImageOps.exif_transpose()` 를 먼저 적용하세요.**
> 안 하면 세로로 찍은 사용자는 전부 오인식됩니다. 파이프라인에서 가장 깨지기 쉬운 지점입니다.

### 정사각형 입력이 글자를 뭉갰음

표지판은 가로세로비 중앙값이 4.8로 매우 납작합니다.
224×224 정사각형으로 찌그러뜨리니 글자가 뭉개져 "4,3 나가는 곳"과 "3,4 나가는 곳"을 구분하지 못했습니다.

입력을 **128×448 가로형**으로 바꾸자 **정확도 63.6% → 90.9%**. 단일 변경으로는 가장 큰 효과였습니다.

### 좌우반전 증강은 금지

표지판은 화살표 방향(←/→)과 숫자 순서가 서로 다른 클래스를 가르는 단서입니다.
뒤집어 학습하면 쌍둥이 표지판을 영영 구분하지 못합니다. `fliplr=0.0` 을 유지하세요.

### 클래스 불균형

클래스당 학습 장수가 10~44장으로 4배 차이 나서, 많은 클래스가 적은 클래스를 흡수했습니다.
`WeightedRandomSampler` 로 고르게 뽑도록 했습니다.

### ResNet50은 과했음

학습 데이터가 1,048장뿐이라 2,360만 파라미터는 과합니다.
ResNet18로 바꾸니 **정확도는 오히려 소폭 상승**(91.1% → 92.9%)하면서 크기 절반, CPU 속도 2.3배가 됐습니다.

| 모델 | 파라미터 | 크기 | CPU 추론 | 실전 정확도 |
|---|---|---|---|---|
| ResNet50 | 23.6M | 94MB | 76.5ms | 91.1% |
| **ResNet18** | **11.2M** | **45MB** | **33.0ms** | **92.9%** |

> 다만 두 모델의 차이는 사진 1장 수준이라 **"거의 같다"**고 보는 게 맞습니다.
> 크기와 속도 때문에 ResNet18을 선택했습니다.

## 6. 서버 배포 메모

GPU 없이 **CPU만으로도 충분히 돌아갑니다.** 4 vCPU 기준 실측값입니다.

| 시나리오 | 이미지 로드 | 검출 | 분류 | 합계 |
|---|---|---|---|---|
| 원본 4032px 업로드 | 185ms | 93ms | 91ms | 371ms |
| **앱에서 1280px로 줄여 업로드** | 10ms | 88ms | 95ms | **188ms** |

### 꼭 챙길 것

1. **앱에서 이미지를 줄여서 업로드하세요.** 서버 응답이 절반으로 줄고 업로드 트래픽도 10배 줄어듭니다.
   GPU를 다는 것보다 효과가 큽니다.
2. **`imgsz=640`으로 낮춰도 됩니다.** 960 → 480까지 낮춰봐도 정확도가 동일했고 검출이 50ms 빨라집니다.
3. **확신도 0.40 미만은 답하지 마세요.** "표지판이 잘 안 보여요, 조금 더 가까이서 찍어주세요"가
   틀린 안내보다 낫습니다.
4. **메모리는 워커당 약 930MB** (ResNet50 기준, ResNet18은 더 적음). 4GB 이상 인스턴스를 권장합니다.

### GPU 서버가 필요한가

**초당 10건을 넘게 처리해야 할 때만** 검토하세요. CPU 4 vCPU 한 대로 초당 4~5건, 시간당 15,000건을
처리할 수 있어 대부분의 경우 충분합니다. GPU를 써도 이미지 디코드는 CPU 작업이라 전체 시간은
1.8배밖에 안 빨라집니다.

### t2 계열 인스턴스 주의

버스터블 인스턴스는 CPU 크레딧을 소모합니다. t2.xlarge 기준 **시간당 약 2,000건**을 넘게
지속 처리하면 크레딧이 바닥나 응답이 4배 느려집니다. T2 Unlimited를 켜거나 c6i 계열로 옮기세요.

## 8. 다음에 할 만한 것

- **평가셋 확대** — 지금 56장이라 정확도의 오차범위가 ±7%p입니다. 100장 이상이면 개선 여부를
  제대로 판단할 수 있습니다. 특히 41개 클래스 중 절반 정도는 실전 사진이 한 장도 없습니다.
- **val 세트 개선** — 지금 val은 100%로 포화돼 모델 선택에 쓸 수 없습니다.
  촬영 세션이 다른 사진으로 val을 재구성하면 변별력이 생깁니다.
- **"해당 없음" 클래스 추가** — 41개에 없는 표지판이 들어와도 모델은 무언가를 답합니다.
  확신도 임계값이 1차 방어선이지만, 네거티브 클래스를 학습시키는 것이 근본 대책입니다.
- **ONNX / OpenVINO 변환** — CPU 추론이 보통 2~3배 빨라집니다.
- **EXIF 없는 사진 대비** — 메신저로 전달된 사진은 EXIF가 지워집니다. 4방향으로 돌려보고
  검출기가 가장 확신하는 방향을 채택하는 방식이 대비책입니다.
