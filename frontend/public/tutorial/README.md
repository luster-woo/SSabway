## 왜 webp 인가 — 반복 재생을 멈추기 위해서다 (8/6)

원래 GIF 였는데, GIF 는 대부분의 브라우저가 루프 횟수와 무관하게 무한 반복해
**안내가 끝나도 애니메이션이 계속 돌았다.** 애니메이션 webp 는 ANIM 청크의
루프 횟수를 브라우저가 지켜서, 1 로 인코딩하면 **한 번 재생하고 마지막
프레임에서 멈춘다.**

⚠️ 재가공할 때 루프 횟수를 반드시 1 로 넣을 것. `ffmpeg` 의 webp 인코더는
`-loop 1` 이다 (GIF 와 달리 0 = 무한). 0 으로 나간 파일은 ANIM 청크의 루프
필드(2바이트)만 바이너리로 고쳐도 된다 — 8/6 에 실제로 그렇게 고쳤다.

## 원본과 가공

원본은 1280x720 슬라이드(장당 2~4MB, 12장 합계 약 31MB)다. 폰 모달은 폭이 약 360px 이라
그대로 쓰면 4배 과한 해상도를 내려받게 되고, 지하 약전파 구간에서 로딩이 눈에 띈다.
그래서 **여백을 잘라내고 축소**한다. (원본은 저장소에 두지 않는다)

여백 크롭이 핵심이다. 슬라이드는 16:9 안에 콘텐츠가 가운데 몰려 있어서, 그대로 폰 폭에
맞추면 글자가 읽히지 않는다. 특히 `video-call` 은 콘텐츠가 가로 45% 뿐이라 잘라내는 것만으로
글자가 2배 커진다.

크롭 박스는 **4개 언어의 합집합**으로 잡는다. 언어마다 문구 길이가 달라(영어가 가장 넓다)
언어별로 자르면 같은 페이지가 언어에 따라 다른 비율이 되고, 모달 미디어 영역 높이가
언어를 바꿀 때마다 달라진다.

재가공이 필요하면(원본이 갱신되면) 언어별로 모든 프레임의 비흰색 영역 합집합을 구해
아래 명령의 `crop` 값을 정한 뒤 실행한다.

    ffmpeg -i <원본> \
      -vf "crop=W:H:X:Y,fps=12,scale=640:-1:flags=lanczos" \
      -loop 1 -quality 80 <출력>.webp

## PWA precache — 제외 대상이다

`vite-plugin-pwa` 의 기본 globPatterns 에 **webp 가 포함**되므로, 그냥 두면 12장
(약 14MB)이 첫 방문에 통째로 precache 된다. 그래서 `vite.config.ts` 의
`workbox.globIgnores` 에 `**/tutorial/**` 이 들어 있다 — 모달을 처음 열 때
내려오고 그 뒤에는 HTTP 캐시가 받는다. **에셋 경로를 바꾸면 이 제외 패턴도
함께 바꿀 것.** (GIF 시절에는 기본 패턴에 gif 가 없어 자동으로 빠졌었다)
