### 1. 서비스 아이디어 제안 및 발산 (07.08 대면 회의)

WebRTC와 AI를 결합할 수 있는 서비스 후보 4건을 직접 조사·기획하여 제안했습니다.

- **은행 화상상담 + 생체인증**: 기존 비대면 실명확인의 라이브니스 취약점, 인증 실패 시 처음부터 재시도해야 하는 UX 단절, 고령층 접근성 문제를 정의하고, 얼굴인식+신분증 OCR 조합 본인인증 → 화상상담 → 전자서명 가입까지 원스톱 처리 흐름과 고령 고객·보호자 다자간 화상 기능을 설계했습니다.
- **공공기관 민원 화상상담**: 챗봇·텍스트 중심 비대면 민원이 복지 상담 같은 판단형 민원을 처리하지 못하는 문제와 부처별 인증 파편화를 정의하고, 판단형 민원 한정 화상상담 창구와 얼굴인식 기반 로그인 간소화를 제안했습니다. 법적 효력·보안 규제상 개념검증 수준의 의의라는 한계까지 함께 정리했습니다.
- **화상+게임보드 통합 보드게임 플랫폼**: 기존 툴(Tabletop Simulator 등)의 화상 부재, 디스코드+게임 앱 조합의 화면 전환 단절을 짚고, 화상 타일과 게임보드 UI를 한 화면에 통합하고 WebSocket으로 게임 상태를 실시간 동기화하는 구조를 제안했습니다.
- **온라인 밴드 합주 플랫폼**: 싱크룸·Jamulus 등 기존 툴의 화상 기능 부재와 장비 진입장벽을 조사하고, WebRTC 오디오 옵션 커스터마이징 기반 웹 합주 서비스를 제안했습니다. 압축/비압축 트레이드오프와 초저지연 성능 한계 등 기술 리스크도 함께 검토했습니다.

- **Q&A 구조화**: 발표 필수 항목에 맞춰 "왜 이 문제가 생겼는가(다층 역사 구조, 낯선 교통카드·환승·출구 번호 체계, 지하 GPS 부정확, 행동 단위 안내 부재, 해외카드 미지원) → 지금은 어떻게 해결하는가(행인·역무원에게 질문, 구글맵 등으로 큰 경로만 확인) → 고객이 원하는 대안은 무엇인가(내 시선 중심의 AR·시각 가이드, 지하 정밀 측위, 결제 수단 글로벌 표준화, 가입 없는 QR 웹 접근)" 구조로 정리했습니다.
- **핵심 결론 정교화**: 기존 지도 앱은 "A에서 B까지의 경로"는 제공하지만 "지금 서 있는 지점에서 당장 어느 방향으로 가야 하는지"는 제공하지 못한다는 점을 근거로, 서비스 포지셔닝을 "경로 안내"가 아닌 **"현재 위치·표지판 기반 행동 단위 안내"**로 명확히 했습니다.

### 4. 페르소나 및 사용자 시나리오 설계

- **페르소나 작성**: 한국 첫 방문 프랑스인 자유여행객 Emma(27)를 설정했습니다. 언어 수준(영어 기본 회화, 한국어 불가)을 명시해 표지판을 읽지 못하는 근거를 만들고, "복잡한 다층 구조에서 방향 상실(원인) → 표지판·지도 앱 반복 확인(행동) → 경로가 맞는지 불안(감정)"의 인과 구조로 다듬었습니다. PoC 대상인 대구역 1호선 환승 상황으로 조정하고, 발권·교통카드 충전 불편까지 반영해 "역 진입부터 환승을 거쳐 목적지 출구까지 전체 이동 흐름 안내"라는 니즈를 도출했습니다.
- **시스템 소개 문서 구조 설계**: 페르소나 → 서비스 개요(가치 제안) → 핵심 기능 → 사용자 시나리오 → 기존 서비스 대비 차별점 → 시스템 구성도 → 화면 구성 → 기대 효과 순서로 기획서 목차를 잡았습니다.
- **사용 시나리오 구체화**: ① 역내 QR 스캔으로 웹 진입(무가입) → ② 목적지·경로 설정 → ③ 촬영 가이드라인에 맞춰 표지판 촬영, AI가 노드-엣지 그래프에서 현재 위치 파악 → ④ 승차권 발매·교통카드 충전 필요 시 편의시설 경유 경로 안내 → ⑤ 이동 중 표지판·개찰구·출구 번호 인식으로 경로 확인 → ⑥ 해결이 어려우면 WebRTC 실시간 화상 상담 → ⑦ 출구 표지판으로 도착 확인의 7단계 흐름을 정리했습니다.

### 5. 표지판 체계 조사 및 위치 인식 방식 설계

- **표지판 표준화 실태 조사**: 기본 사인 시스템(노선색, 출구 노란색, 국·영문 병기 등)은 존재하지만, 운영사(교통공사·코레일 등 구간별 상이)·건설/리모델링 시기·표지판 종류에 따라 서식·색·글꼴이 달라진다는 점을 확인했습니다. 이 "표준화 부족 + 높은 정보 밀도"가 외국인 혼란의 실제 원인이자, 이미지 인식 모델이 다양한 서식을 다뤄야 하는 기술 난이도임을 정리했습니다.
- **유도 표지 vs 식별 표지 구분**: 천장 표지판이 방향을 알려주는 유도 표지(출구·환승 방향, 화살표 포함)와 현재 위치를 알려주는 식별 표지(역명판·출구 번호판·시설명판, 화살표 없음)로 나뉨을 조사했습니다. 화살표가 없는 표지판이 존재하고 유도 표지에는 여러 방향이 함께 표기되므로, **표지판의 화살표를 읽어 방향을 정하는 방식은 위험**하며, **표지판으로는 위치만 특정하고 이동 방향은 자체 지도에서 계산하는 방식**을 채택해야 함을 팀에 공유했습니다.
- **표지판 중복 문제와 해법 설계**: 동일 문구의 유도 표지가 역내에 반복 설치되어 단일 이미지로는 위치가 특정되지 않는 문제를 확인했습니다. 해법으로 출구 번호·승강장 방면·환승 통로처럼 **역내 고유 정보를 담은 표지판을 위치 앵커로 우선 사용**하고, 반복 표지판은 보조로만 활용하며, 이미지 유사도·OCR 결과·이전 이동 노드(직전 앵커+이동 방향)를 결합하는 다중 신호 위치 판정 구조를 설계했습니다. 노드-엣지 그래프의 각 노드에 해당 지점에서 보이는 표지판을 앵커/보조로 구분해 태깅하는 데이터 구조를 정리했습니다. (컨설턴트님 과제 "층별 구별 요소 찾기"와 연결)
- **참고 자료 수집**: 서울시 "지하철 보행자를 위한 안내 체계" 자료, 지하철 안내표지 개선 사례, 표지판 유형별 예시 이미지를 수집해 팀 참고 자료로 정리했습니다.

### 6. 실내 지도 데이터 및 공공 API 조사

- **실내 구조 데이터**: 국토교통부 실내공간정보(IndoorGML)가 브이월드를 통해 제공되어, 역사 내부를 노드(지점)·링크(통로)와 좌표로 표현할 수 있음을 확인했습니다. 단, 구축된 시설만 데이터가 존재하므로 대구역 포함 여부 확인이 선행 과제입니다.
- **역·시설 정보**: 서울 열린데이터광장(역사 좌표·심도), KRIC 레일포털, 한국철도공사 편의시설 공공데이터(무인발매기·물품보관함·엘리베이터 등)를 조사했습니다. 편의시설 데이터는 "몇 층에 몇 대" 수준의 속성 정보로 실내 정밀 좌표는 제공하지 않음을 확인했습니다.
- **실내 측위 API 부재 확인**: 지하에서 사용자의 현재 위치를 실시간 제공하는 공개 API는 존재하지 않으며, 네이버·카카오도 실내에서는 정확한 위치·방향을 잡지 못함을 확인했습니다. **"실내 지도 데이터는 구할 수 있어도 실내 측위는 직접 만들어야 한다"**는 결론을 얻었고, 이 공백이 표지판 촬영 기반 위치 인식의 존재 이유이자 서비스 차별점임을 정리했습니다.
- **시설 간 거리 산출 구조 설계**: "탑승구→무인발매기 거리"를 바로 주는 API는 없으므로, 시설 목록(공공데이터) + 실내 좌표(IndoorGML 또는 자체 제작 지도) + 그래프 최단경로 계산을 조합해 시설 간 거리·경유 경로를 산출하는 구조를 설계했습니다.
- **대구역 도면 출처 조사**: 대구교통공사 사이버스테이션의 역구내 안내도, 네이버·카카오 실내지도를 확인하고, 도시철도 대구역과 KTX 대구역(코레일)이 운영 주체·건물이 다른 별개 역사임을 구분해 정리했습니다. 상세 평면도의 공개 데이터가 제한적임을 확인하고, **대구역 층별 2D 지도를 직접 제작해 갈림길·개찰구·승강장·출구·편의시설을 노드와 엣지로 표현**하기로 한 팀 결정에 참여했습니다.

### 7. 안내 UX 설계 검토

- **거리 표시 방식 검토**: 표지판을 촬영한 순간에만 위치를 아는 서비스 구조상, 실시간으로 줄어드는 미터 표시는 불가능하고 "27m"식 정밀 표기는 오차 발생 시 신뢰를 무너뜨리는 거짓 정밀도임을 검토했습니다. 이에 따라 주 안내는 **행동+랜드마크**("개찰구를 지나 왼쪽으로"), 보조는 대략적 소요 시간(약 1분)과 진행 단계(Step 2/5), 미터는 10~20m 단위로 반올림한 구간값만 사용하는 우선순위를 정했습니다.
- **체크포인트 방식 안내 흐름 설계**: 각 안내 구간이 "다음에 촬영할 표지판"에서 끝나도록 설계해, 사용자가 긴 거리를 가늠할 필요 없이 "다음 표지판까지"만 이동하면 되는 구조로 정리했습니다. 간헐적 위치 인식이라는 기술 제약을 UX로 흡수하면서 위치 오차 허용과 불안감 감소를 동시에 달성하는 방식입니다.
- **외국인 대상 표현 원칙**: 언어 비의존적인 아이콘·방향 화살표 중심 구성, 짧은 명령형 문장("Turn left at the gates."), 한 화면에 한 행동 원칙을 정리했습니다.
- **진입 UX**: 역내 QR 스캔 → 가입 절차 없는 웹 접속 흐름으로, 리서치에서 확인한 "가입 요구 과다" 불편을 반영했습니다.

## 이번 주 학습 및 느낀 점

- 아이디어의 참신함만큼 **시연 가능성과 데이터 확보 가능성이 주제 선정의 결정적 기준**이 된다는 점을 컨설팅 과정에서 배웠습니다. 대구역 PoC, 싸피 내 시연 환경 구성 같은 대안을 기획 초기부터 준비해야 함을 느꼈습니다.
- 공공 API 조사를 통해 **실내 지도 데이터는 존재하지만 실내 측위 API는 부재**하다는 것을 확인했고, 이 기술 공백을 역에 이미 설치된 표지판이라는 인프라로 메우는 접근이 서비스의 차별점이 된다는 확신을 얻었습니다. 데이터 조사가 곧 설계 방향을 결정한다는 것을 체감했습니다.
- 표지판은 서식이 통일되어 있지 않고 동일 문구가 반복되며 화살표가 없는 유형도 있어, **이미지 한 장으로 위치·방향을 확정할 수 없다**는 점을 배웠습니다. 고유 정보 표지판을 앵커로 삼고 OCR·이전 이동 노드·그래프 연결 관계를 결합하는 다중 신호 판정이 필요한 이유를 이해했습니다.
- 정밀한 수치(미터)가 오히려 신뢰를 떨어뜨릴 수 있다는 UX 관점을 검토하며, **기술 제약(간헐적 위치 인식)은 숨길 것이 아니라 체크포인트형 UX로 설계에 흡수해야 한다**는 것을 느꼈습니다.
- 문제 정의는 팀의 가설만으로 완성되지 않으며, 기사·실태조사 리서치를 통해 결제 장벽·가입 과다처럼 **처음에 놓쳤던 문제가 드러난다**는 것을 경험했습니다.
