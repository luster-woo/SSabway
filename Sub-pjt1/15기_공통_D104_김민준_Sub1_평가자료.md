## 1. 공부한 내용

### 요구사항 명세서 작성법

요구사항 명세서의 기본 구조(개요–기능 요구–비기능 요구–인터페이스)를 공부했다. 기능 요구사항(FR)과 비기능 요구사항(NFR)을 구분하는 이유, `FR-USR-001`처럼 영역별 접두사로 ID를 관리하는 방식, 삭제된 요구사항의 번호를 재사용하면 히스토리 추적이 꼬이기 때문에 번호를 영구 보존해야 한다는 원칙을 알아봤다.

### 설계 강의 정리

설계 강의에서 들은 내용을 노션에 정리해 팀에 공유했다. 핵심은 API 명세보다 ERD를 먼저 확정할 것("데이터를 어떻게 저장하지?"부터 답하기), 발표 시연을 기준으로 필수 기능을 상/중/하로 나눌 것, 필수 기능 테이블만 확정하고 출발할 것, API 명세를 바꾼 사람이 바꾼 즉시 팀 채널에 공지할 것. 툴은 ERDCloud, Swagger, Postman을 쓰기로 했다.

### 경로 탐색 알고리즘

역내 경로 안내에 쓸 알고리즘으로 가중치 없는 양방향 그래프의 최단 경로를 공부했다. 간선 비용이 전부 같으면 BFS로 처음 도달한 시점이 곧 최단 거리라는 원리, 이전 노드 배열로 경로를 복원하는 방법, O(V+E) 시간 복잡도까지 확인했다.

### 개발 환경·협업

- GitLab MR 설명 템플릿과 컨벤셔널 커밋 적용 방법을 공부했다. git worktree가 뭔지도 이번에 알게 됐는데, 작업 폴더는 나누되 저장소는 하나로 공유한다는 점에서 폴더 복사와 다르다는 걸 이해했다.
- Jira–Mattermost 연동을 진행하며 인스턴스 연결과 채널별 subscribe의 개념 차이, 학생 계정 권한으로 되는 것과 관리자가 해야 하는 것을 구분하는 시행착오를 겪었다.
- PoC를 위해 miniforge(conda)로 가상환경을 만들고 OpenCV 환경을 세팅했다.

## 2. 프로젝트 기여

### 아이디어 회의·회의록 작성

코치님 1차 회의에서 아이디어 4개에 대한 피드백을 받았고, "AI 기반 외국인 입국·이동 동행 서비스"가 참신성 면에서 가장 좋은 평가를 받았다. 컨설턴트님이 합류한 2차 회의에서 토론 배틀 아이디어와 둘로 압축한 뒤 최종 주제로 확정됐다.

두 회의 모두 회의록을 작성해 노션에 공유했고, 받은 피드백 — 라이브 시연 환경(대구역 허가 또는 싸피 내 환경 구성), 지하에서 GPS가 부정확한 문제, 카메라 사용에 따른 프라이버시 이슈 — 을 기획에 반영할 과제로 정리했다.

### 기술 검증(PoC)

역내 위치 인식에 쓸 수 있을지 OpenCV 기반 이미지 유사도 매칭(색상 히스토그램 + ORB 특징점 + pHash 가중 평균)을 직접 돌려봤다. 리사이즈나 약한 편집이 들어간 거의 동일한 이미지는 잘 잡지만, 의미적으로 비슷한 장면은 못 잡는 한계가 확인돼 채택하지 않기로 했다. 목표, 접근 방식, 검증 결과, 보류 사유, 대안(딥러닝 임베딩)까지 개발 기록으로 정리해 노션에 남겼다.

### 데이터·도구 조사

- 지하철역 편의시설 정보를 가져올 수 있는 공공데이터 API(레일포털 편의시설, 국토부 TAGO 지하철정보)가 있는지 조사했다.
- 역 내부를 층별 노드 그래프로 그릴 수 있는 맵 에디터를 AI로 생성해서 써봤다. 안내도 이미지 위에 노드·통로를 찍고 SQL로 내보내는 방식이라, 팀이 역 내부 경로 데이터를 직접 구축하는 데 쓸 수 있을지 확인했다.
